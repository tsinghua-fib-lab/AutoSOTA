# When More Agents Break the Market: Scaling Failure and Recovery in 1000-Agent Coupled Markets

我们研究多智能体系统在 coupled market中的可扩展性问题。此类市场天然包含大量同质化但相互依赖的买卖双方 agent，是评估大规模多智能体系统的理想测试床。然而，现有多智能体方法几乎从未在数百到上千 agent 的 coupled market 场景中进行系统验证。

我们的核心发现是：在 coupled market 中，agent 数量的增加会导致学习与更新机制的系统性失效。当市场参与者规模扩大时，单个 agent 接收到的市场信号变得高度噪声化，局部最优行为在市场层面产生强烈耦合效应，最终导致策略更新相互干扰、价格发现机制失灵，整体市场效率不升反降。这种现象表现为一种典型的 scaling-induced failure，而非简单的训练不充分或参数设置问题。

基于这一失效现象，我们进一步指出：coupled market 场景不仅放大了多智能体系统的交互复杂性，也使得 token 消耗与 API 调用成本呈现灾难性增长，使得在 500–1000 个 agent 规模下的实验在现实硬件条件中几乎不可行。这一现实约束使得“大规模多智能体市场”长期停留在概念层面。

在此基础上，我们的工作分为两个阶段：
（1）系统性地刻画并验证多智能体系统在 coupled market 中随 agent 数量增长而发生的性能退化与机制失效；
（2）在明确失效来源后，探索改进更新与通信机制的方法，以降低单 agent 的 token 消耗和 API 调用频率，使得在现实资源约束下构建 500 甚至 1000 个 agent 的 coupled market 成为可能。

通过这一研究，我们不仅揭示了大规模多智能体系统在真实市场机制中的结构性问题，也为未来大规模、低成本、多智能体市场模拟与部署提供了新的设计思路。

## 计划

### 1.Agent 数量扩充与失效验证
从现有的小规模 coupled market 系统出发，在不引入任何新机制的前提下，系统性地扩展 agent 数量（例如从 60 增加到 200、500 直至 1000）。在这一过程中，保持 agent 的策略更新规则和通信方式不变，重点观察市场效率、价格稳定性以及 agent 更新行为是否随规模增长出现退化。该阶段的目标是明确验证：多 agent 系统在 coupled market 中是否会因规模扩展而发生结构性失效。

当前进展：已完成  100/300/500/800/1000 个 agent 的实验。

### 2.通信与计算瓶颈
在 agent 数量扩展的同时，系统统计不同规模下的 token 消耗、API 调用次数和运行成本，分析其随 agent 数量增长的变化趋势。通过这一阶段，在 500–1000 个 agent 规模下，现有多智能体系统在现实硬件与成本约束下难以运行的问题，从而将“大规模多智能体市场”从概念问题转化为可量化的工程与系统瓶颈。重点分析在 agent 数量增加时，一次性大量 agent 同步通信所带来的系统瓶颈，并评估通过**多线程 / 多进程 / Docker 容器化并行** 等方式缓解通信阻塞和调度压力的可行性。

该阶段的目标是明确：在不改变学习机制的前提下，大规模 agent 系统在现实计算资源下的可运行边界。

当前进展：**通信与并行瓶颈已解决**（多线程/并行方案已部署），500–1000 agent 规模在现有资源下可稳定运行。后续可补充：各规模下的 token 消耗、API 调用次数与总耗时等量化数据，用于论文中的「可运行边界」与成本分析。

### 3.引入 OpenClaw 长记忆机制
在确认 scaling 失效和资源瓶颈后，引入 OpenClaw长期记忆方法作为跨 episode 的长时记忆模块。OpenClaw长期记忆方法：采用文件首位（File-first）跨会话记住项目背景，通过语义搜索和混合索引（BM25 + 向量搜索）检索相关知识。

### 4.基于长记忆的更新机制重构
基于 OpenClaw 的长记忆，重新设计 agent 的更新流程，使其能够利用历史聚合经验进行低频、方向性更强的策略更新，从而减少无序探索和相互干扰。该机制旨在降低单 agent 的 token 消耗和 API 调用频率，同时缓解由于 agent 数量增加而导致的学习噪声放大问题。

### 5.大规模恢复性验证
在引入长记忆更新机制后，再次将 agent 数量扩展至 500 甚至 1000 个，对比引入前后的市场效率、学习稳定性和计算成本。通过该阶段验证：在合理的记忆抽象和通信机制支持下，多智能体系统在 coupled market 中可以从 scaling-induced failure 中恢复，并展现出可扩展的性能提升趋势。
